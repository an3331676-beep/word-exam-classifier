# 试卷归集台

这是一个纯前端的多份 Word 试卷整理工具。它在浏览器本地读取 `.docx`，可提取选择题、填空题、英语阅读理解或英语完形填空，按上传顺序从 1 连续编号，并把已匹配的答案解析放到文末。

## 使用

```powershell
npm install
npm run dev
```

浏览器打开终端显示的本地地址，先单选目标题型，再选择多份 `.docx`。核对文章、题目边界和答案匹配后，可导出 Word，或使用浏览器打印功能保存 PDF。切换题型不会重新读取文档。

生产构建：

```powershell
npm run build
```

构建结果位于 `dist/`，可以部署到普通静态文件托管服务。

## 已实现

- 多份 `.docx` 批量读取，坏文件不会中断其余文件。
- 保留段落、表格、Word 自动编号、内嵌图片和 Office Math 公式节点。
- 识别选择题、填空题、英语阅读理解、英语完形填空栏目；解答题仍保留为内部兼容类型。
- 按 `Passage A`、`Text B`、`第一篇`、`A篇` 等文章标签分组；没有标签时自动建立一个文章组。
- 阅读和完形材料只保留一次，所属小题连续排列，并跨多份文档从 1 重新编号。
- 保留独立的参考答案章节，按原题号和文章标签匹配，在输出文档末尾按文章顺序生成答案与解析。
- 重复答案编号、无法唯一关联的答案和不可靠边界会进入待核对区，不会静默猜测。
- 按来源文件和原题号追溯题目。
- 人工改题型、按段落边界拆题、合并相邻题、把漏识别片段加入题目。
- Word 导出时重新映射跨文档图片关系，避免同名图片互相覆盖，并保留 Office Math 公式。
- A4 打印样式，可通过浏览器“打印”保存 PDF。

## 发布到 GitHub Pages

项目已包含 `.github/workflows/deploy-pages.yml`，推送到 GitHub 后可自动测试、构建和发布静态网页：

1. 在 GitHub 创建一个空仓库，将本地 `main` 分支推送到该仓库。
2. 打开仓库的 **Settings → Pages**。
3. 在 **Build and deployment** 中选择 **GitHub Actions**。
4. 再次推送到 `main`，或在 **Actions** 页面手动运行 **Deploy static site to Pages**。
5. 部署完成后，打开部署任务显示的 Pages 地址。

工作流会自动判断用户主页仓库与普通项目仓库的路径差异。应用不会把用户选择的 Word 内容提交到项目服务器，所有解析和导出都在访问者的浏览器中完成。GitHub Pages 作为托管服务，可能按照其常规安全机制记录访问者 IP 等请求日志。

## 当前边界

- 输入格式为可编辑的 `.docx`。旧 `.doc` 需要先另存为 `.docx`。
- 整页扫描图片没有可编辑文字时会提示走扫描识别流程。
- 同一段落或同一个表格单元格中排了多道主问题时，页面会提示核对。复杂的段内拆分建议先在原 Word 中分段。
- 自动编号支持常见十进制主编号。多级自定义编号、文本框、SmartArt、特殊域和部分浮动对象需要人工核对。
- PDF 输出调用浏览器打印对话框。为获得最稳定的公式和复杂对象效果，也可以打开导出的 Word 后另存为 PDF。
- 答案若没有题号，会按同一来源中的下一个未匹配小题尝试关联；复杂合并段落仍应在待核对区人工确认。
